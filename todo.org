Roadmap and design notes for features not yet implemented. Done items live in
git history; this file is the "what next / what was decided" scratchpad.

* Open items

** TODO Correctness / edges
- sort: the in-memory budget is *soft* — N workers can each =fetch_add= before any
  spill, so peak memory may exceed =--sort-buffer= by ~N blocks (=sort.rs:389=).
  A string sort key containing a literal =\0= (rare in CSV) sorts slightly off
  (documented in CLAUDE.md).

** DONE Numeric-vs-string footgun resolved (per-row auto for bare-column orderings)
=select qty > stock= used to compare *lexically* (=\"100\" < \"9\"=). Resolved by a
third comparison mode =CmpMode::Auto= (=plan.rs=; decided in the =parse.rs=
expression parser): an ordering (=< > <= >=) between two untyped columns now
auto-detects *per row* — numeric when both cells parse as numbers, else lexical.
Reproducible (a function of the two values, not a sampled type) and never aborts;
the successful =f64= parses are reused, so it tracks an explicit =to-num= within
noise (benchmarked). =to-str= pins a column back to lexical. ===/!== between bare
columns stay lexical (float equality is fragile). Visible as =:auto= under
=--print-engine=. The =num()= coercion alternative was dropped — auto fixes the
default without new syntax.

** TODO Decisions to make
- Sort vs select numeric-detect asymmetry (follow-up to the auto-compare work
  above): =select a > b= on two untyped columns now auto-detects numeric per row,
  but =sort a= stays *lexical* by default (its own =SortKey.numeric=, set only by
  =a=n= or a prior =to-num=). So =select qty > stock | sort qty= filters by
  numeric magnitude yet orders =100= before =9= as text — a surprising mismatch on
  the same column. Decide: give =sort= an analogous per-key auto-detect default
  (changes the default order for every untyped column — a bigger behavioural
  change, needs an escape hatch like =sort a=s= to force lexical), or leave the
  asymmetry as-is (documented in =help types= / CLAUDE.md) since a streaming sort
  can't cheaply sample types. Leaning: document-only for now; revisit if it bites.

- Column ranges / indices: =cols 1-5=, =cols a:e=, =$3= positionals (wide data).
- Join naming sugar: kill the per-file =(rename value=X | cols -v metric)=

- Multiple input files: =csvm SCRIPT a.csv b.csv= — concatenate inputs sharing a

* DONE computed column: =add NAME EXPR=
Implemented: =Stmt::Add= + the =ValExpr= value engine (=plan.rs=), parsed by a
sibling recursive-descent parser sharing =select='s tokenizer (=parse.rs=). The
starter scope below shipped — arithmetic, =++= concat, ternary, a bare
comparison as a =t=/=f= value, the function set, replace-in-place, and abort on
divide-by-zero / non-numeric. Cross-row =prev(col)= and =rownum()= are included
(chosen over a separate Miller-style =step= verb): an =add= reading them is
order-dependent, so it routes to the in-memory ordered path (like =tail=/=uniq=),
keeping output =-n=-independent; a pure =add= still shards. =prev(col)= on the
first row reads the current cell, so =amount - prev(amount)= is 0 there.

Still deferred (follow-ups): =split=, regex =match=, and date functions; grouped
=prev=/delta (=… by g=) once group-by lands.

** DONE unified comparison operands + math functions
Comparison operands (=Cmp= in =plan.rs=) are now full =ValExpr=s, so arithmetic
(=select price * qty >= 30=), functions (=abs(x) > 1=), and parenthesized
boolean subexpressions compared as =t=/=f= (=(a >= 0) == (b >= 0)=) work in
=select=, ternary tests, and =color= predicates. The =CmpMode= decision
generalized to static expression types (=ExprParser::static_type=). Leaf
operands keep the old allocation-free fast path (=cmp_num=/=cmp_str= with
=#[inline(never)]= compound fallbacks — benchmarked ~equal to the old
=Operand=). A stateful =select= (=prev()=/=rownum()=) routes to the ordered
in-memory path like a stateful =add=; =color= rejects stateful at parse time.
New functions: =sqrt/pow/exp/log/log10/log2/sign= (IEEE at domain edges, e.g.
=sqrt(-1)= is NaN — no abort). =coalesce= is now statically untyped (its result
type follows the data), so comparisons against it auto-detect instead of
assuming numeric.

Original design notes (kept for the deferred parts):
Append a new column =NAME= computed per row from a value expression over the
existing columns. If =NAME= already exists, replace it in place (so
=add price round(price * 1.1)= works). Appends at the end otherwise; reorder
with =cols= afterward.

Implementation: extend the =select= expression parser so the grammar yields a
typed *value* (number or string), not just a bool. =select EXPR= then requires
a bool-valued expression; =add NAME EXPR= takes any. Compiles to a Plan node
evaluated per row — no interpreter in the hot path, same as today.

** Categories + examples
*** Arithmetic (=+ - * / %=, parens, precedence)
#+begin_src sh
add total   amount * qty
add net     gross - tax
add margin  (price - cost) / price * 100
add price   price * 1.1            # replaces 'price' in place
#+end_src
*** Functions (a small standard set)
#+begin_src sh
add a   round(price)          # round / floor / ceil / abs
add lo  min(bid, ask)         # min / max
add n   len(name)             # string length
add g   upper(grp)            # upper / lower / trim
add v   coalesce(nick, name)  # first non-empty
add k   int(price)            # truncate / parse to integer
#+end_src
*** Strings (concat + extraction; use =++= or =concat()=, never overload =+=)
#+begin_src sh
add full  first ++ ' ' ++ last
add dom   split(email, '@', 1)      # nth part
add area  match(phone, '(\d{3})')   # regex capture group
#+end_src
*** Conditional (ternary, reusing the bool expression for the test)
#+begin_src sh
add tier  amount > 1000 ? 'big' : 'small'
add sign  amount < 0 ? 'debit' : 'credit'
#+end_src
*** Constants & metadata (tags; useful before a concat)
#+begin_src sh
add source  'january.csv'    # constant column
add rownum  rownum()         # 1-based row index
#+end_src

** Design decisions to make
- Typing: arithmetic ⇒ numeric column; string ops ⇒ string. Column refs coerce
  by context (implicit, like =select=). Numbers format like =to-str= (trimmed).
- String concat operator: prefer =++= (or only =concat(...)=) so =a + b= is
  always numeric and unambiguous.
- Replace vs append when =NAME= exists: lean *replace* (enables in-place
  transforms). Alternative: =add= must be new, a separate =set= must exist.
- Booleans: should =add ok amount > 0= yield ='t'/'f'= or =1/0=? (csvm-ish: t/f.)
- Errors: divide-by-zero / non-numeric in arithmetic — abort with a message
  (consistent with =to-num=) rather than yielding empty. Lean abort.
- Starter function set: round, floor, ceil, abs, min, max, len, upper, lower,
  trim, coalesce. (split / regex-extract / date functions come later.)

** Recommended starter scope
Arithmetic + comparison/ternary + the function set above + string =++=, with
=add= replacing an existing name. Covers the bulk and reuses the expression
parser. =split= / regex / date functions are a follow-up.

* TODO color: future extensions
The =color= command (predicate + =-g= gradient, =--color auto|always|never=) is
implemented (=src/color.rs=, =exec::render=). Still open:
- Palette: =bright-*= and 256/named-extended colours, and explicit =#rrggbb= /
  =rgb(r,g,b)= so a ramp isn't limited to the 8 base names.
- 3-stop diverging ramp =lo:mid:hi= centred on a value (default the column mean
  from =ColStats=), for z-score-style heatmaps.
- A =color= rule referencing a column other than the one painted (=color -c qty
  red amount < 0= already works; document the cell-vs-predicate-column split).
- Combinable gradients (=-g=). Today a ramp is two *plain* names and paints the
  *foreground only* (=parse_ramp= → names; =Ramp::at= sets just =fg=); the
  =+=/=bg:=/attribute combining works only in the predicate forms. Lift this so a
  gradient can carry a uniform style:
  - background gradient (heatmap): interpolate the =bg= channel instead of =fg=.
  - attributes on every gradient cell (=bold=/=dim=/=underline=).
  - optional flat second channel (e.g. fg gradient over a fixed =bg:gray=).
  Endpoints stay plain names (interpolation needs RGB, and the attributes are
  uniform across the ramp anyway). Proposed spelling: trailing bare modifiers
  after the ramp/bounds, =color -g amount green:red 0 100 bg+bold=, reusing the
  gradient parser's token-peeking (=:=-token = ramp, two numbers = bounds, else a
  modifier). =Ramp= grows a fixed =Style= + an fg/bg target; =Ramp::at= ORs them
  in. Pairs naturally with the =#rrggbb= and 3-stop-ramp items above.

* DONE group-by aggregation =group COLS | agg FNS=
Implemented: =Stage::Group= (=GroupStmt=/=AggSpec=/=AggFunc= in =plan.rs=), the
=Grouper= reducer in =exec.rs= folding rows into a =HashMap<key, GroupAcc>= in
first-seen order, reusing one =ColStats= per distinct aggregated column. Both
spellings ship (=group COLS | agg FNS=, fused; =agg FNS by COLS=; bare =agg= ⇒
one global row). Funcs: =count/sum/min/max/mean/stddev= (bare =count= = rows,
=count(col)= = non-empty). Streaming + sharded fast paths now ship too (mirroring
=stats=; see the graph follow-ups-done list). Original notes:

Prerequisite for =graph bar= (categorical charts), and useful on its own — the
sibling of the =stats= profiler, which already reduces to one row *globally*;
group-by reduces to one row *per key*.

Spelling (decide): one verb =agg sum(amount),mean(price) by region= (Miller-ish),
or two stages =group region | agg sum(amount)=. Lean two stages — it reuses the
=cols=-style key parser for =group= and keeps =agg='s function list orthogonal,
and a bare =group region= with no following =agg= can default to a count.

Mechanics: a blocking, *reducing* stage like =stats=. Hold a
=HashMap<key, Vec<ColStats>>= (one =ColStats= per aggregated column per group),
streaming each row into its group's accumulators — O(groups x aggregated-cols)
memory, not O(rows). Output schema = key cols ++ one column per requested
aggregate (=region,amount_sum,price_mean=). Emit groups in first-seen order
(stable) or sorted by key — pick first-seen, =sort= composes after.

Aggregates from =ColStats= for free: =count/sum/min/max/mean/stddev= (and
=empty=). =median=/quantiles/=distinct= are the same not-cheaply-mergeable
problem flagged for =stats --full= (t-digest/HLL) — defer identically.

Parallelism: like =stats= over a seekable file with =-n>1=, each worker builds a
partial =HashMap= over its byte range and a merge folds them (=ColStats::merge=
already does the Welford combine per group; just union the key sets). stdin/=-n1=
stream single-pass. Same ~1-ULP float caveat as sharded =stats=.

* DONE graph: terminal-native charts
All rollout phases shipped (hist/bar/spark/scatter/line + SVG); see the
follow-ups subsection for what remains. Original design notes kept below.
A render-time *sink* stage that consumes the pipeline and draws a chart to the
terminal — the visual sibling of =fmt=. Decided design (2026-06-15):

** Why terminal-native (not PNG/SVG)
csvm is a one-shot Unix-pipe CLI with no rendering deps beyond ANSI. Draw with
Unicode block / *braille* (=U+2800=, 2x4 sub-cell pixels) straight to the
terminal, reusing =color.rs='s truecolour SGR + =Ramp=. Keeps the "point it at a
CSV, get an answer" flow and the lean dep tree. PNG/SVG export stays a *later*,
feature-gated =--svg out.svg= — not the default.

** =graph= is a blocking terminal sink
Structurally a sibling of =fmt= (=Plan.output= mode / render-time metadata), but
it *terminates* the pipe: it emits a chart, not CSV, so anything after =graph= is
an error. Like =fmt=/=tail= it can't stream the final draw, but bin/raster
accumulators keep it O(canvas), *not* O(rows) — preserving the past-RAM promise.
Do the data work upstream; =graph= just consumes:
#+begin_src sh
csvm 'select region == "EU" | graph hist amount' sales.csv
csvm 'group region | agg sum(amount) | graph bar region amount_sum' sales.csv
csvm 'graph scatter price qty' sales.csv
#+end_src

** Chart types, ranked by memory fit (= ship order)
The deciding axis is memory, because csvm's bragging right is "scales past RAM".
- =graph hist COL [--bins N] [--log]= — O(bins), streaming. *Best fit, ship
  first.* Auto-bin (Freedman-Diaconis / Sturges); bounds from =ColStats=.
- =graph spark COL= — one-line inline chart, downsample to width. Trivial.
- =graph bar LABEL VALUE= — O(categories). Needs group-by upstream. Horizontal
  bars scaled to terminal width; the chart people actually ask for.
- =graph scatter X Y= / =graph line X Y= — a fixed braille canvas *is* a
  streaming accumulator: set pixels, don't store points, so O(canvas). line
  needs x binning/sorting to bound memory.

** Features it needs
- Terminal-size aware: query =$COLUMNS=/=$LINES= (ioctl), fall back 80x24,
  =--width=/=--height= overrides. Reuse =unicode-width= for visible-width
  accounting (as =fmt= does).
- Axis auto-scale + override (=--xrange lo:hi=, =--yrange=, =--log=); bounds from
  =ColStats=. Axis ticks, title (=--title=), the unglamorous readability 60%.
- Color via =color.rs= ramps for free: gradient bars / scatter-density color.
- Multi-series (=graph line x y1,y2=) — design the column grammar for it from day
  one even if single-series ships first.
- =--ascii= / =--color never= fallback: degrade braille -> ASCII (=* # -=) for
  dumb terminals and when piped to a file, mirroring =--color auto|always|never=.

** Non-goals
- No interactive TUI / ratatui / zoom-pan (that's a different tool; csvm is
  one-shot). No new expression syntax — =graph= consumes columns the existing
  language already produces; pipe =add=/=select=/=group= upstream. No plotting
  crate as a hard dep (a braille renderer is ~200-300 LOC we control).

** Sharp edge to settle early
The numeric-vs-string footgun bites here: a "mostly numeric with one =N/A=="
column wrecks an axis. =graph= must be *strict and loud* — count non-numeric /
empty cells, drop them from the plot, and print =(skipped 12 non-numeric rows)=
below the chart rather than coercing to 0. Settle this before the binning code.

** Rollout (each phase shippable)
1. [X] group-by aggregation (above) — the =graph bar= prerequisite, useful alone.
2. [X] =graph hist= + the block render core (=src/graph.rs=) + terminal sizing
   (=$COLUMNS=) — proved the sink-stage (=Plan.graph=, =exec::render_graph=) +

3. [X] =graph bar= (diverging, zero-baseline, capped at =MAX_BARS=) + =graph

4. [X] =graph scatter= / =line= on a 2x4 braille canvas (=Braille=, Bresenham

5. [~] SVG export shipped (=--svg=, =src/svg.rs=, hand-written XML, no dep, so

* DONE Parquet read (optional =parquet= feature)
First cut of the pluggable-format roadmap. Feature-gated (=--features parquet=
pulls =parquet=+=arrow=+codecs) to keep the default dep tree lean. =src/parquet.rs=
wraps the arrow =ParquetRecordBatchReader=; selected by a =.parquet= extension or
=--format parquet=; needs a seekable file (footer metadata), so stdin/=hdr=/
=--no-header= are rejected. The schema gives header *and types* — numeric columns
decode to =Field::Num= (no =to-num= needed), bool ⇒ =t=/=f=, null ⇒ empty; only
flat primitives are supported (others error by name). =exec::run_parquet= streams
a lone transform batch-by-batch, materializes for blocking stages. =gen_parquet=
example writes fixtures; CI runs a =--features parquet= clippy+test job.

** DONE Row-group-parallel parquet reads
A pure-transform read with =-n>1= now shards across row groups
(=run_parquet_sharded=/=process_row_groups=/=partition_row_groups= in =exec.rs=;
=ParquetReader::open_row_groups= in =parquet.rs=): contiguous per-worker blocks,
outputs concatenated in file order — the parquet mirror of CSV's =run_sharded=.
~3.2x on 4 cores (benchmarked, 3M rows); =-n1=/=-n4= byte-identical. A single-row-
group file can't shard. Blocking stages (group/sort/…) still take the
single-threaded materialize path. =gen_parquet= now writes multiple row groups.

** TODO Projection push-down (parquet) — only decode the columns the plan needs
Parquet is columnar, so an unused column's chunk can be skipped on disk
entirely. Today =batch_to_rows= decodes *every* column of every batch into
=Field=s even when the plan never reads them — pure waste on a wide file (a
2-of-50-column query still reads + decompresses + transposes all 50). Pushing a
projection into the arrow reader cuts I/O + decode to the columns actually used;
the reader side is one call (=ParquetRecordBatchReaderBuilder::with_projection=
with a =ProjectionMask=). The work is *deciding what to project*.

*** The crux: "needed columns" is a liveness question, not "columns mentioned"
- =select EXPR= filters *rows* but keeps *all columns*, so unless a later
  =cols=/=group=/=agg=/=stats= narrows the output, the plan still emits every
  column ⇒ needs every column. Push-down only helps when output + all reads use a
  strict subset.
- =cols a,b= narrows to {a,b}; =cols -v x= *drops* x ⇒ needs the complement (most
  columns). =add NAME EXPR= adds a column derived from input cols (its refs are
  live); =rename= just relabels.
- =group COLS | agg FN(col)= / =stats col= reduce to a known subset (keys ∪
  aggregated cols) — the highest-value case, and unambiguous.
So the needed set is a *backward liveness* pass over the plan: which input columns
transitively affect the output. It must be exhaustive across every position
holder — =ColRef.pos=, =ProjectStmt=/=ConvStmt= =.positions=,
=GroupStmt.key_positions= + =AggSpec.pos=, =SortKey.pos=, =ValExpr::Col=, join
keys — because a missed ref ⇒ wrong column or panic.

*** Mechanics
1. =plan::live_input_columns(&Plan, &input_header) -> Option<Vec<usize>>=: the
   minimal ascending input indices, or =None= = "need all" (the safe fallback for
   a passthrough =select=, =cols -v=, or anything the analysis can't prove a
   subset of).
2. On =Some(cols)=: build the =ProjectionMask= from those leaf indices *and
   resolve the plan against the projected sub-header* — positions shift (=name= at
   input idx 7 → idx 1). Reorders =main='s =read_header → resolve= flow (resolve
   needs the projected header) or keeps a remap table.
3. Each sharded worker applies the same projection (=open_row_groups= grows a
   projection arg) — composes cleanly with the row-group sharding.

*** Scope / staging
- Soundness over coverage: push down only when =live_input_columns= *proves* a
  strict subset (leading =cols=, or =group=/=agg=/=stats= naming their columns);
  otherwise =None= ⇒ read everything (correct, just no speedup). Never under-read.
- Test: a wide fixture — projected output byte-identical to the full read for a
  subset query, and an all-columns query falls back. Bench projected vs full.
