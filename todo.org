* TODO computed column: =add NAME EXPR=
Append a new column =NAME= computed per row from a value expression over the
existing columns. If =NAME= already exists, replace it in place (so
=add price round(price * 1.1)= works). Appends at the end otherwise; reorder
with =cols= afterward.

Implementation: extend the =select= expression parser so the grammar yields a
typed *value* (number or string), not just a bool. =select EXPR= then requires
a bool-valued expression; =add NAME EXPR= takes any. Compiles to a Plan node
evaluated per row — no interpreter in the hot path, same as today.

** Categories + examples
*** Arithmetic (=+ - * / %=, parens, precedence)
#+begin_src sh
add total   amount * qty
add net     gross - tax
add margin  (price - cost) / price * 100
add price   price * 1.1            # replaces 'price' in place
#+end_src
*** Functions (a small standard set)
#+begin_src sh
add a   round(price)          # round / floor / ceil / abs
add lo  min(bid, ask)         # min / max
add n   len(name)             # string length
add g   upper(grp)            # upper / lower / trim
add v   coalesce(nick, name)  # first non-empty
add k   int(price)            # truncate / parse to integer
#+end_src
*** Strings (concat + extraction; use =++= or =concat()=, never overload =+=)
#+begin_src sh
add full  first ++ ' ' ++ last
add dom   split(email, '@', 1)      # nth part
add area  match(phone, '(\d{3})')   # regex capture group
#+end_src
*** Conditional (ternary, reusing the bool expression for the test)
#+begin_src sh
add tier  amount > 1000 ? 'big' : 'small'
add sign  amount < 0 ? 'debit' : 'credit'
#+end_src
*** Constants & metadata (tags; useful before a future join/concat)
#+begin_src sh
add source  'january.csv'    # constant column
add rownum  rownum()         # 1-based row index
#+end_src

** Design decisions to make
- Typing: arithmetic ⇒ numeric column; string ops ⇒ string. Column refs coerce
  by context (implicit, like =select=). Numbers format like =to-str= (trimmed).
- String concat operator: prefer =++= (or only =concat(...)=) so =a + b= is
  always numeric and unambiguous.
- Replace vs append when =NAME= exists: lean *replace* (enables in-place
  transforms). Alternative: =add= must be new, a separate =set= must exist.
- Booleans: should =add ok amount > 0= yield ='t'/'f'= or =1/0=? (csvm-ish: t/f.)
- Errors: divide-by-zero / non-numeric in arithmetic — abort with a message
  (consistent with =to-num=) rather than yielding empty. Lean abort.
- Starter function set: round, floor, ceil, abs, min, max, len, upper, lower,
  trim, coalesce. (split / regex-extract / date functions come later.)

** Recommended starter scope
Arithmetic + comparison/ternary + the function set above + string =++=, with
=add= replacing an existing name. Covers the bulk and reuses the expression
parser. =split= / regex / date functions are a follow-up.

* TODO conditional colours when formatting
Colourize =fmt= output (and maybe plain output to a TTY) based on per-row /
per-cell conditions — like a spreadsheet's conditional formatting, or what
tools like =tidy-viewer= / =csvlens= do.

** Command syntax (pinned)
A separate =color= command appends a rule to the plan (like =fmt= sets the
output mode); position in the pipe doesn't change semantics, but write it just
before =fmt=. Multiple =color= commands stack. Rules render with or without
=fmt=; =--color auto|always|never= gates emission (auto = only when stdout is a
TTY). Two rule kinds, switched by the =-g= flag:

*** Conditional (predicate) — solid colour
#+begin_src sh
color COLOUR EXPR            # paint the whole row when EXPR is true
color -c COL COLOUR EXPR     # paint only COL's cell
#+end_src
=COLOUR= comes first (a single token, so it splits cleanly), then a bare
=select=-style expression — reuses the expression parser and backtick column
quoting, no new grammar. Examples:
#+begin_src sh
color red amount < 0
color bold+bg:red status == 'error'
color -c amount yellow amount > 1000
#+end_src

*** Gradient (heatmap) — value-based
#+begin_src sh
color -g COL [RAMP] [LO HI]   # colour COL's cells by where they fall in a range
#+end_src
=RAMP= is =locolour:hicolour= (e.g. =green:red=), interpolated in truecolour, and
defaults to =green:red= when omitted. =LO HI= are optional numeric bounds;
default the column's min/max (from =ColStats=), and values outside the range
clamp to the endpoint colours. (A ramp token always has a =:=, so it's never
confused with a numeric bound.)
#+begin_src sh
color -g amount                    # default green:red, bounds = column min/max
color -g amount blue:yellow        # custom ramp
color -g amount green:red 0 5000   # explicit bounds, solid outside
#+end_src

*** Colour vocabulary
- fg: the 8 ANSI names (=red green yellow blue magenta cyan white black=), =gray=.
- bg: =bg:NAME=.
- attrs: =bold=, =dim=, =underline=.
- combine with =+=: =bold+red=, =white+bg:red=.
- (=bright-*= / 256 / truecolour names are a later extension; =RAMP= already
  lerps truecolour.)

*** Layering [decision — can flip]
Rules apply in order; each sets only the attributes it names, later rules layer
on top (so =color red … | color bg:yellow …= ⇒ red-on-yellow when both match,
and a =-g= foreground composes with a predicate =bg:=). Alternative is
first-match-wins per cell; pinned to *layering, last wins per attribute*.

** Implementation notes
- Rules evaluate against the *output* rows at render time, so column refs
  resolve against the output header (after =cols=/=rename=), not the input.
- ANSI escapes must NOT count toward =fmt='s column-width alignment — pad by
  *visible* width, not byte length. (=format_aligned= pads by =chars().count()=;
  it must measure the uncoloured text.)
- =--color auto|always|never=: default =auto= (colour only when stdout is a
  TTY), so piping to a file or another tool stays clean. Needs an isatty check.
- A =color= rule is plan-level metadata (a =Vec<ColorRule>=, like =output=), not
  a row-processing stage; =parse= validates the colour/ramp and compiles the
  predicate to a =BoolExpr=.

** Value-based (heatmap) colouring — reuses =stats='s =ColStats=
The =color -g= form above. The per-column min/max/mean/stddev already exist as
=ColStats= (=src/stats.rs=), the accumulator behind =stats=. =fmt= computes its
*own* =ColStats= over the rows it renders — it never receives them from a =stats=
stage (in =stats | fmt= the rows *are* the profile), so the reuse is at the
*type* level, not a shared instance.
- Mechanics: =t = clamp((v-lo)/(hi-lo), 0, 1)=, then lerp =RAMP='s endpoints; the
  clamp yields the solid-outside behaviour for free. Bounds default to =ColStats=
  min/max, =LO HI= overrides.
- =mean=/=stddev= ride along in =ColStats=, so z-score / diverging colouring (a
  3-stop =lo:mid:hi= ramp centred on the mean) reuses the same struct.
- Put the mapping in a small =color= module (=value, lo, hi, ramp -> ANSI=),
  shared with the predicate rules; both need fmt to pad by *visible* width.
- Keep =ColStats= presentation-free (compute only) so =stats= and =fmt= both use it.
